# Framework and source map

This app turns Martin's supplied playbook into guided practice while preserving its core method. Source labels distinguish Dan Martell's principles from proposed exercises and product decisions. This personal learning handoff is not an official Dan Martell course.

## User confirmed preferences

These requirements come from Martin's answers and discussion:

- He is familiar with most AI tools and does not consider himself a beginner.
- He wants deeper practice in prompting and task mapping.
- He can allocate approximately 6–8 hours per week.
- He will mainly use a phone or tablet.
- He wants to learn the existing method through application before changing what works.
- His business direction involves helping businesses in his area solve practical problems with AI.

Optional refreshers, practical exercises, resumable sessions, and touch-friendly mapping are design recommendations based on these preferences.

## Dan's original principles and their app representation

The left column describes the uploaded source [D1]; the right contains assistant recommendations for teaching it.

| Original principle | Proposed app representation |
| --- | --- |
| **AI Buyback Loop: Audit → Transfer → Fill.** Identify work to offload, transfer it, then deliberately use released capacity. | Record the current task, transfer attempt, and use of recovered time in a repeated project cycle. |
| **Camcorder Method.** Capture a task and use its recording or transcript to create instructions. | Ask for steps, decisions, exceptions, and an SOP draft; allow typed notes when recording is impractical. |
| **AI Replacement Ladder: Admin → Delivery → Marketing → Sales → Leadership.** A progression for reclaiming the owner's time. | Preserve the named ladder. Choosing the learner's first project from an observed bottleneck is an app recommendation. |
| **Four-part deployment process.** Audit opportunities; choose tools and map the workflow; test and measure; standardize and expand. | Use these project stages to produce a problem brief, workflow map, pilot result, and repeatable procedure. |
| **Master Prompt and RCCF.** Establish business context, then specify Role, Context, Command, and Format. | Separate reusable context from the task request. Compare outputs after changing an instruction or supplying better evidence. |
| **Department prompt library.** Prompts support marketing, sales, customer success, product, engineering, and operations. | Organize optional examples by actual tasks, so a solo learner can select relevant work. |
| **Review and measurement.** Inbox sending and scheduling require approval; deployment includes weekly output reviews and before/after measures. | Inspect results, record corrections, and compare total handling effort and output quality. |

Dan's broader teaching uses **10–80–10** for human ideation, AI execution, and human integration/review [D3]. Present it as a delegation heuristic, not a stopwatch requirement or performance guarantee.

## Assistant design recommendations

Label these additions as app design recommendations:

- Use a short explanation, worked example, attempt, feedback, and real application. Completion should require evidence of understanding, beyond opening a page.
- Give prompting and task mapping extra practice. Mapping should expose the trigger, inputs, decisions, steps, result, checks, and responsible person. The extended worksheet is our teaching structure, building on Dan's workflow pattern.
- Include discovery exercises before proposing a client solution. Dan's separate seven-step guide supports learning from potential customers and validating demand [D2]; local examples and interview worksheets are our implementation.
- Ask learners to separate observed facts, assumptions, and unknowns. Test both an ordinary example and a difficult case, then inspect the actual result [T1]. Keep the testing proportionate to the task.
- Record checking time, corrections, tool costs, and realized benefits. Freed capacity, additional revenue, profit, and cash savings should have distinct labels.
- Use illustrative practice targets only. The playbook's 80–90% automation aspiration, the seven-step guide's margin figures, and any sample income goals are not promises or pass marks.

Change a workflow when a real requirement or measured result supplies a reason. Let the learner try the framework before redesigning it.
